What each part does

  1. 1Filter header, one job per row. Search, the Active / Archived / All tabs, grouping and a view menu replace a row of separate icon buttons. The status chips double as the summary: a chip takes its tone only while its count is above zero.
  2. 2Active card. Running and needs-you threads share one raised card (bg-card, border-border, shadow-xs). It reads as a summary, not as a group.
  3. 3Group headers are where you triage. Sentence case, muted, led by the section’s own icon. An attention pill appears only when something needs you; the total is a quiet count.
  4. 4The needs-you row. One pill and one breathing dot; nothing else is boxed. A medium title outranks its neighbours. Project and PR share one muted line; the PR is tinted only when it needs action.
  5. 5Hover swaps the time for controls. Pin, Archive, Details, More. This is bb’s own pattern: the trailing status fades and the controls appear. Rename moves into More; double-click still renames.
  6. 6Folded family summary. “3 replies · 1 needs you” states the loudest hidden state without opening the family. Only read, idle rows go muted.
  7. 7Details, in place. A definition list: goal, status, model and thinking, host, branch with copy, PR, context. Open and Split live only here, so no action repeats on the same screen.
  8. 8Spool with a member pip. The count carries a spinner while a member runs. Members hang from one roster guide. Section view only.

Same data, rendered two ways. What the proposed version removes is what competed with the title.

  • Boxes: six bordered chips become one pill and some text.
  • Status: a 9px uppercase shout becomes a 10px sentence-case word, and only where action is needed.
  • Time: from a chip at the start of the line to a right-aligned figure.
  • Unread: a bold title and an ink dot, the same signal bb’s own sidebar uses.
